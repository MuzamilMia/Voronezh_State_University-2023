Значит, такая шина обеспечивает три виды передачи. Те которые реально используются. ЦП - ОП, ЦП - интерфейс, ОП - интерфейс.

АЛУ здесь регистровая память, регистр флагов и выполняемая операция. Устройство управления соответственно содержит программный счетчик, регистр адреса, регистр команды. Регистр адреса содержит адрес команды который выполняется, регистр команды содержит команду которая выполняется. Есть генератор тактовой частоты обеспечивающий синхронизацию работы всех устройств. Его назначение выдавать ритмично сигналы электрические, по которым будут ориентироваться другие устройства. Дальше есть устройство памяти и внешние устройства, и шины. Шина это тоже устройство, это не просто провод. Есть шины адреса, шины данных, шины управления. Память это характеризуется адресом данными и управлением. Каким образом здесь происходит работа с памятью. В памяти когда требуется доступ к памяти, ЦП обращается к данным, которые необходимы, он должен обратиться к памяти, это все хранится в ОП, для этого нужно на шину, если выбираем данные, на шину адреса положить адрес что именно читать будем, во-вторых по шине управления передать сигнал, если мы считаем, соответственно что требуется именно считывание. Память получит команду, она положит на шину данных данные которые затребованы, а по шине управления отправит сигнал, чтобы получили данные. 
Управляющая шина используется в обе стороны, шина данных тоже. Аналогичным образом связаны порты устройства ввода вывода. Уже упоминалось, что процессор общается непосредственно со внешними устройствами, а через специальные регистры интерфейс. Называются портами. То есть это специальные регистры и соответственно они тоже содержат ту же самую информацию, которая необходима для общений внешних устройств, адрес по которому происходит обращение, то есть адрес может указывать какой именно из устройств будет востребовано, куда происходят данные. Либо записываются на внешнее устройство либо считываются, и управляющий сигнал соответственно показывает что именно будет делаться. Чтение или запись.
Структура компьютера
Цифровой компьютер состоит из связанных между собой процесосров модулей памяти устройства ввода вывода, все это связано шиной.
ЦП - это мозг компьютера. Его задача - выполнять программы находящиеся в основной памяти. Он вызывает команды из памяти, определяет их тип, выполняет одну за другой. Это как автомат, счетчик команд, после выполнения команды передвигается дальше. В тот момент когда выполняется команда счетчик команд уже указывается на следующюю. Это автомат который бесконечно выбирает команду выполняет и т. д. Сами команды хранятся в памяти, в это революционная идея Фон-Неймана, которые положила начало всему развитию компьютеров. Он Компоненты соединены шиной, представляющей собой набор параллельно связанных проводов, по которым передаются адреса, данные и сигналы управления. Шины могут быть внешними (связывающими процессор с памятью и устройства ввода-вывода) и внутренними. Когда рассматривали тракт данных там внутри тоже есть шина. Возвращаясь к самому началу, говорили что компьютер это система, она может состоять из подсистем. Вот в свою очередь здесь компьютер состоит из различных устройств, в свою очередь процессор часть этого устройства и это тоже сложная система внутри нее свои подсистемы.
ЦП состоит из нескольких частей. Блок управления УУ отвечает за вызов команд из памяти и определяет их типа. И АЛУ выполняет арифметические операции и логические тоже.
Память процессора. Внутри ЦП есть память для хранения промежуточных результатов и некоторых команд управления. Эта память состоит из нескольких регистров, каждая из которых выполняет определенную функцию. Только что рассмотрели различные архитектуры наборы команд. Обычно размер все регистров одинаков. Каждый регистр содержит одно число, которое ограничивается размером регистра. Регистры считываются и записываются очен быстро, поскольку они находятся внутри ЦП. Технически она быстрее память регистров, и во-вторых они находятся внутри процессора, не нужен сценарий считывания из ОП.
Внутреннее устройство тракта данных типичного фон-Неймановского процессора.
Есть регистры, в них есть операнды, они поступают на вход в АЛУ, здесь есть входная шина АЛУ, на выходе из АЛУ выходной регистр и по шине выходной в выходной регистр.
Большинство команд можно разделить на две группы. Типа регистр-память и типа регистр-регистр. Команды первого тип вызывают слова из памяти и помещают их в регистры, где они используются в качестве входных данных АЛУ. АЛУ Работает с регистром, не работает с ячейкой памяти. Предварительно эти данные приходят к регистр. Команды первого типа вызывают слова из памяти помещают их в регистры где используются в качестве входных данных. Другие команды этого типа помещают обратно регистры в память. Команда выполняется как здесь нарисовано. Команды второго типа вызывают два операнда из регистров, помещают их во входные регистры АЛУ, выполняют над ними операцию и переносят результат обратно в один из регистров, этот процесс называется циклом тракта данных.
ЦП выполняет каждую команду за несколько шагов.
Вызывает следующую команду из памяти и переносит ее в регистр команд. (А откуда вызывается из памяти. Она вызывается из памяти в соответствии со счетчиком команд, счетчик команд указывает всегда адрес следующей команды. В соответствии с этим значением счетчика адреса выбирается следующая команда памяти и переносится в регистр команд. Как уже говорилось, поскольку команда выбрана, то понятен ее размер. В разных архитектурах размер команд различный. После первой выборки счетчик команд указывает на следующий байт, где находится либо продолжение, если команда занимает несколько байтов либо это уже будет следующая команда. По первому байту можно определить сколько места занимает эта команда. Поэтому дальше возможно потребуется выборка оставшейся части, то есть этой команды в том числе операндов. которые требуются. А в тех архитектурах где все команды одинаковой длины, там вот этих сложностей не возникает.
Меняет положение счетчика команд, который после этого указывает на следующую команду
Определяет тип вызванной команды
Если команда использует слово из памяти, определяет, где находится это слово.
Переносим слово, если это необходимо в регистр ЦП

Независимо от компьютера последовательность шагов выборка - декодирование - выполнение является основой работы всех компьютеров.
Соответственно можно написать программу имитирующую работу ЦП. То есть мы сейчас немного уходим в сторону, когда мы говорили про быстродействие и стоимость. На эту тему рассуждения, что бывают такие компьютеры, которые достаточно дорогие, потому что команды которые там выполняются сложные. Можно написать программу которая имитирует работу ЦП. И значит, программа не обязательно должна выполняться реальным процессором. Вызывать из памяти, определять тип команд и выполнять эти команды может другая программа. Такая программа называется интерпретатором. Программы-интерпретаторы, которые имитируют работу процессора, широко используются при разработке компьютерных систем. 
Шаг который тут выполнение, будет выполняться не самим командами процессора, а с помощью более простых команд. 
После того как разработчик выбрал машинный язык для нового компютера, он должен решить разрабатывать ему процессор, который умеет эти команды выполнять или написать программу для интерпретации программ на том же языке. То есть если он решить написать интерпретатор, ему потребуется разработать АО для выполнения этого интерпретатора. Возможны также гибридные конструкции когда часть команд выполняется АО, а часть интерпретируется. Можно на более медленном компьютер выполнять эти операции, это по времени будет дольше. Требуется разрабатывать более сложный компьютер который умеет делать эти команды. Если стоимость, то можно сделать просто интерпретатор.
Интерпретатор разбивает команды на более мелкие элементарные. В результате машина предназначенная для выполнения может быть гораздо проще по стоимости и выполнению чем АО.
Некоторые операции могут выполняться параллельно. Вопрос параллельности немножко касались. Для дорогих компьютеров с высокой производительностью приобретение дополнительного АО оправдано у дорогих компьютеров больше команд чем у дешевых. Но развитие ПО и требования совместимости команд привели к тому что сложные команды стали использоваться и в дешевых компьютерах, хотя там ставилась стоимость а не быстродействие. Выполнение этих команд за счет интерпретации было достигнуто. 
К концу 50-ых годов, команда IBM, решила что производство семейства компьютеров, каждый из которых выполняет одни и те же команды выгоднее и для самой команды и для покупателей. До этого времени каждый компьютер был сам по себе. Создавать семейство компьютеров, ввела термин архитектуры. Новое семейство должно было иметь единую архитектуру и много разных моделей, различающихся по цене и скорости, но умеющих выполнять одни и те же программы.
Но как построить дешевый компьютер который сможет выполнять все сложные команды. Решение проблемы стала интерпретация. Еще один фактор в пользу интерпретации. Есть одна сложная команда, потребуется 10 команд. И 2 обращения к ОП, общее время 2000 а если бы не было специального быстродействующего постоянного запоминающего устройства выполнение этой команды заняло бы 6000
Не говорю о том, что интерпретация 2000 а выполнение сложной команды на родном компьютере, где эта команда заложена оно естественно будет существенно меньше. Но говорим, что интерпретация используется когда стоит вопрос цена и объем выполняемых данных. За счет снижения быстродействия.
Системы RISC и CISC. Это классификация RISC с сокращенным набором команд, где простые команды выполняются, а CISC это компьютеры у которых полный набор команд Reduced/Complex instruction set computer. Тот ассемблер который мы смотрели был CISC. Откуда возникла идея создать RISC компьютеры. С сокращенным набором команд. теоретически можно подвести базу из следующих рассуждений. Было показано, исследование показали, что 33% типичной программы это пересылка данных, 20% условные ветвления, 16% АЛО, в подавляющем большинстве команд вычисление адреса может быть выполнено быстро, за один цикл. более сложные режимы адресации используются примерно в 18% случаев. Около 75% операндов являются скалярными, а остальные являются массивами и структурами. 80% скалярных переменных являются глобальными. 90% структурных являются глобальными. Таким образом большинство операндов - это локальные операнды скалярных типов. А это значит их можно просто хранить в регистре. Как вы знаете работа с регистрами существенно быстрее.

Принципы RISC
Все команды должны выполняться непосредственно АО то есть мы говорим, что RISC быстрые.
Компьютер должен запускать как можно больше команд в секунду (распаралеллиование)
Команды должны легко декодироваться
К памяти должны обращаться только команды загрузки и сохранения
Регистров должно быть много. Содержат примерно несколько сотен регистров. В асемблере который мы рассматривали было 20.
Набор команд должен быть ограниченным и включать только простые команды, время выполнения которых после выборки и декодирования один такт или чуть больше. То есть все команды выполняются за один такт.

Простую команду RISC процессор выполняет за такт, а сложную за 14, длительность такта 75нс
